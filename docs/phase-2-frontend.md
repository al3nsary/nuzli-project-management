# المرحلة 2 — الواجهة: الفرق والأعضاء والبيانات المرجعية وكروت العمل

> آخر تحديث: 2026-10-13. يكمّل `docs/phase-1-frontend.md`. القرارات في ADR-051 إلى ADR-055. العقد في `docs/API.md` (المرحلة 2) مع فروق التنفيذ في `docs/phase-2-backend.md`.

## البيانات

- `src/api/client.ts`: أُضيفت إلى `ApiClient` مجموعات `colors` و`teams` و`members` و`reference` و`cards` و`logos` لكل نقاط المرحلة 2. و`HttpApi` ينفّذها كما هي، ومنها رفع الشعار (presign ← PUT ← confirm ← `POST /logos`) وطلب PDF كملف.
- `src/api/demo/phase2.ts`: محوّل العرض بالقواعد نفسها: الألوان المتاحة تستبعد المحجوزة (نشط + معلّق)، و`COLOR_TAKEN` مع `ColorTakenDetails` (ويُحاكى السباق بمعاملة Dexie)، وحالة فريق المشرف حسب الإعداد مع إشعار المديرين، و`ALLOW_MULTIPLE_TEAMS_PER_SUPERVISOR`، ونطاق المشرف (فرقه وغير المسندين، وفريق غيره = 404)، والنقل في معاملة واحدة بلحظة واحدة (يُغلق الصف المفتوح ويُفتح جديد، وصف مفتوح واحد لكل عضو)، ورفض النقل كله عند `MEMBER_ALREADY_IN_TEAM` مع `details.memberIds`، والأرشفة تحرّر اللون وتجعل الأعضاء بلا فريق، وتفرّد رقم الهوية، ومعاينة الاستيراد بأخطاء كل صف ثم حفظ الصحيح فقط، وإخفاء الهوية في المعاينة حسب القالب، وعدم تكرار الدفعة بالمفتاح، والحفظ في سجل العضو، و501 لـ PDF، والشعارات PNG/JPEG/WebP فقط بفحص البايتات (SVG مرفوض)، وسجل التدقيق بأسماء الإجراءات نفسها.
- فروق التنفيذ في الخادم مطبّقة في المحوّلين: `GET /teams` دون حالة = النشطة والمعلّقة (و`ALL` للكل)، و`DELETE /reference` يعيد `{ result, item }`، وحذف الشعار يفكّه من القوالب.
- `src/features/members/importRows.ts`: قراءة اللصق (Tab أو فاصلة أو «،» مع تعرّف سطر العناوين) وملف ‎.xlsx‎ في المتصفح (exceljs عند الطلب)، والتحقق المشترك بين المعاينة المحلية ومحوّل العرض.
- بيانات العرض في `seed/demo`: `colors.json` (لوحة الخادم نفسها، ٢٤ لونًا)، و`teams.json` (٧ فرق: ٥ نشطة، وواحد معلّق، وواحد مؤرشف، مع سجل المشرفين)، و`members.json` (٤٠ عضوًا بأرقام هوية مولّدة صحيحة، ٥ بلا فريق، وبعضهم بسجل نقل)، و`reference.json`، و`cards.json` (المقاسات الستة والقوالب الثلاثة كما في بذرة الخادم، وشعار محايد مولّد PNG). المتصفحات التي بُذرت في المرحلة 1 تأخذ بيانات المرحلة 2 تلقائيًّا (`seededPhase2`).

## RTL

- الإزاحات الماديّة تمرّ بـ `src/lib/direction.ts` (`dirSign()` و`scrollInline()`): «الأعمدة التالية» تمرّر نحو نهاية السطر، فتصير `scrollLeft` سالبة في RTL (تحقّقنا: ‎−308‎ عند 360px).
- التمرير التلقائي أثناء السحب مكتوب يدويًّا بإحداثيات ماديّة لأن الماسح المدمج في dnd-kit يفترض أن `scrollLeft` تزيد يمينًا (ADR-052).
- الأدراج تفتح من جهة نهاية السطر، والأسهم الدالّة على الاتجاه معكوسة بـ `mirror-rtl`.

## الاختبارات

٤٨ اختبارًا ناجحًا في ٥ ملفات (منها ٢٢ جديدًا):
- `src/api/demo/DemoApi.phase2.test.ts` (١٩): اللون المستخدم لا يُعرض ويعود بعد الأرشفة، ولون الفريق نفسه عند التعديل، وسباق اللون (ينجح طلب واحد والآخر `COLOR_TAKEN` بقائمة جديدة)، وفريق المشرف معلّق مع إشعار المديرين ثم نشط عند إطفاء الإعداد، و`MULTIPLE_TEAMS_DISABLED`، ونطاق المشرف، وافتراض `GET /teams`، وسجل المشرف بلحظة واحدة، والنقل (صف مغلق ومفتوح بالطابع الزمني نفسه وصف مفتوح واحد)، ورفض النقل كله، والفريق غير النشط، وتفرّد الهوية، ومعاينة الاستيراد وأخطاؤها ثم الحفظ الجزئي، والمعاينة وإخفاء الهوية وQR بالمعرّف، وعدم تكرار الدفعة والحفظ في السجل، والتعديل للدفعة فقط، والشعارات (SVG مرفوض)، والمقاسات المدمجة، والمرجعية، ومنع مشرف المراقبة.
- `src/pages/phase2.render.test.tsx` (٣): أعمدة التشكيل بأسماء الفرق ومشرفيها (النشطة فقط)، وحجبها عن المشرف، ومحرّر الكرت يعدّل المعاينة الحيّة.

الفحوص: `npx tsc --noEmit && npx vitest run && node scripts/check-i18n.mjs && npx vite build && npx vite build --mode demo` — كلها ناجحة. والتحقق البصري بلقطات Chrome بلا واجهة (CDP) على 360×740 و1440×900 فاتحًا وداكنًا: الفرق، ونافذة الإنشاء، وتفاصيل الفريق، والتشكيل (مع التمرير والتحديد)، والكروت (القالب والمعاينة)، وصفحة الطباعة (وُسِم `@page { size: 85.6mm 54mm; margin: 0 }`، واستُدعيت الطباعة مرة واحدة بعد تحميل الخطوط)، والقوالب، واللوحة، والمعايرة، والأعضاء — دون تمرير أفقي للصفحة.
